# EmbeddPilot V1.6 — Input Layer Round: Report

Scope: fix only how a job gets configured. No chat, no repo/app-code generation.
The generator-is-never-the-judge separation, the subprocess validator, and the
contamination guard are untouched — this round only changes what enters the
pipeline.

Test status: **75 passed** (52 pre-existing + 23 new). UI: `tsc --noEmit`,
`eslint`, and `next build` all clean. Live `arm-none-eabi-gcc` compile captured
(see Priority 3).

## Priority 1 — Silent auto-fill killed

### Every auto-fill path found (enumeration required by the spec)

| # | Location | Field | Old silent behavior | Now |
|---|----------|-------|---------------------|-----|
| 1 | `ingestion/pipeline.py` (map assembly) | chip | `chip or basename(path)` — **invented the chip from the upload filename** (URL → `<jobid>_download`). This is the reported bug. | Removed. Chip is user-supplied (`user`), high-confidence detected (`detected_unconfirmed` until confirmed), or empty. |
| 2 | `generation/worker.py` `generate_driver` / `build_worker_prompt` | chip | `.get("chip", "device")` → literal `"device"` | Reads `register_map["chip"]`; guarded by the provenance assertion. |
| 3 | `generation/worker.py` `build_worker_prompt` | peripheral/interface | `.get("peripheral","")` → prompt label `"peripheral"` | Reads `register_map["peripheral"]`; guarded. |
| 4 | `ui/InputScreen.tsx`, `ui/app/page.tsx` | platform | `useState("esp32")` — silent UI default | Platform default is `""`; an explicit dropdown selection is required. |
| 5 | `generation/router.py` | chip | `.get("chip","")` routed on empty | Unreachable now — the provenance guard runs before `route()`. |

`api/main.py` download zip name used `chip = "driver"` — cosmetic (zip filename
only, never fed to the worker); left as-is.

### The rule now enforced

New `generation/inputs.py :: assert_input_provenance(register_map, platform)`.
Every one of {chip, peripheral/interface, platform} must be **detected** (from
the document, confirmed on review) or **blocked** (specific, field-naming
error). Never a third option.

- Provenance lives in the map: `provenance.{chip,peripheral}` ∈
  `user | detected | detected_unconfirmed | null`. Only `user`/`detected` pass.
- Enforced at **three** points: the API `/api/generate` boundary (→ 422 with the
  field named), the pipeline entry (before the router), and again at worker
  prompt construction (`build_worker_prompt` calls the same assertion and fails
  loudly — the "construction fails loudly" requirement).
- The worker prompt therefore can never receive a chip/interface/platform value
  of unknown provenance.

### Tests (`tests/test_input_provenance.py`)

- empty fields → blocked, error names the field
- empty platform → blocked
- detected-but-unconfirmed → blocked
- invented value (value present, provenance unknown) → blocked / assertion fails
- user & confirmed-detected → pass
- **regression** reproducing the exact bug: a datasheet ingested under a random
  `<jobid>_download.pdf` name never yields a filename-derived chip; and a
  no-detection document leaves chip empty and is blocked.

## Priority 2 — Auto-detection from the document

New `ingestion/detect.py`, run during ingestion. Detects from the front matter
(first 6 pages): chip/part-number, vendor, interface(s), and a device-shape
hint. Each value carries `confidence` + `source_pages` evidence — same
provenance discipline as register extraction. Detection is **suggestion, never
decision**: a single high-confidence value pre-fills as `detected_unconfirmed`;
multiple interfaces are surfaced as a choice and never auto-picked; low/no
confidence leaves the field empty (Priority 1 blocks it).

### Detection accuracy on the four known datasheets

| Datasheet | Chip (conf) | Vendor | Interfaces | Notes |
|-----------|-------------|--------|-----------|-------|
| BMP180 | BMP180 (high) | Bosch | I2C | single → pre-fills |
| BME280 | BME280 (high) | Bosch | **I2C + SPI** | multi → forces an explicit choice (not auto-picked) ✓ |
| W25Q64JV | W25Q64JV (high) | Winbond | SPI | exact printed token kept |
| ESP32 TRM | ESP32 (high) | Espressif | I2C, SPI, UART | controller/memory-mapped case; interfaces surfaced as choices |

What it gets wrong / limits (honest): detection is front-matter + known-family
based. Known families (BMxxx, BMExxx, W25Qxx, ESP32, MPU6050, ADXL3xx, LSM6DS…)
are high confidence; anything else falls to a generic part-number heuristic
(medium/low, never high) which can pick a wrong token on unusual title pages —
by design that stays `detected_unconfirmed` and the user must confirm. The
shape-hint is a UI hint only; the router still routes from the map itself.

Tests: `tests/test_detection.py` — the four datasheets (skips gracefully if a
PDF is absent), the multi-interface case, and a no-detection case.

## Priority 4 — Link input: validate and demote

- `api/main.py :: preflight_url` runs **before** a job starts: scheme check,
  reachability (HEAD, GET-range fallback for 403/405/501), content-type must be
  PDF/DOCX (a `.pdf`/`.docx` path also accepted for servers that send
  octet-stream), and Content-Length ≤ 50MB. Any failure → a specific 422
  naming the problem (unreachable / not a document / too large / bad scheme).
  Never a silent fallback to a partial extraction.
- UI: the URL field is demoted beneath the file upload behind an "or extract
  from a URL instead" disclosure, with a note that uploading the file extracts
  more reliably (the engineers' own finding).
- Tests: `tests/test_link_validation.py` — ok pdf, octet-stream+.pdf,
  unreachable, HTTP error, wrong content-type, oversize, non-http scheme.

## What deviated / decisions made

- **Chip/interface entry moved off the input screen.** To honor "less manual
  entry", the input screen now asks only for the file (or a demoted URL) and an
  optional page range. Chip, interface, and platform are confirmed on the review
  screen where the detection evidence is shown. A user who wants to override
  still does so there (flipping provenance to `user`).
- **`peripheral` is treated as the interface field** (the spec uses
  "`peripheral`/interface" interchangeably). The BME280 sample was given a
  concrete `I2C` interface so the confirmed-sample path still generates.
- **Sample + demo maps** were given `provenance: {chip:user, peripheral:user}`
  so the live-proven samples and the recorded-demo mode still pass the new gate.
- **Raspberry Pi / "Other"** fall back to an available compiler for portable-C
  warning coverage when their exact toolchain isn't installed; this is labeled
  honestly (compiler shown in the UI; unrecognized-platform note in the report)
  rather than being presented as a target-accurate compile.

## Unchanged (verified)

WS2 validator behavior, the three-state verdict logic, the router's map-based
routing, the subprocess boundary, and the contamination guard all still pass
their original tests.
