# V1.7.1 — Cost Estimate (complete-driver run)

Real token counts from the live V1.7 **BME280-on-STM32F4-I2C** run
(`openai/gpt-oss-120b`, NVIDIA endpoint, `response.usage`), priced against
current published rates. This is the number the provider decision should be made
on.

## Measured tokens

**First attempt (measured exactly via `response.usage`):**

| Component | Tokens |
|---|---|
| System / instruction prompt | ~761 |
| Device map + worker instructions | ~3,416 |
| MCU-map section (clock/GPIO/peripheral) | ~2,025 |
| **Input total (measured `prompt_tokens`)** | **6,318** |
| **Output (measured `completion_tokens`, incl. reasoning)** | **6,944** |

Note: `completion_tokens` (6,944) exceeds the visible code (~5,200 tokens) because
gpt-oss is a reasoning model — reasoning tokens are billed as output.

**Per-retry overhead (targeted-edit echo):** each retry re-sends the failing
file (~1,300–1,500 tokens) + the validator error text (~200 tokens) on input;
output is another full generation (~6,944). Input-only grows; the maps are sent
once and are identical across attempts (candidates for prompt caching — see
below).

## Cost — gpt-oss-120b is priced identically across the major hosts

All three checked hosts publish **$0.15 / 1M input, $0.60 / 1M output** for
`gpt-oss-120b` (Aug 2026): Groq, Together AI, Fireworks AI. So provider choice is
driven by *window/licensing*, not headline token price.

| Case | Cost / run | Cost / 50 runs / month |
|---|---|---|
| First-attempt pass | **$0.0051** | **$0.26** |
| 3-attempt run (observed live) | **$0.0159** | **$0.79** |

At $0.15/$0.60, a complete-driver run costs **half a cent to ~1.6 cents**;
50 runs/month is **under $1**. Token cost is not a meaningful constraint —
licensing and window size are the real decision inputs (see V1.7.1 README /
Task 2). OpenRouter lists a lower input rate (~$0.037/1M) but variable per
upstream; the three first-party hosts above are the stable reference.

## Not a per-run cost

- **MCU reference-manual ingestion is deterministic (pdfplumber) and cached** —
  **zero LLM tokens**. It runs once per MCU (~13s CPU for RM0090, section-
  targeted), producing `artifacts/mcu_cache/<mcu>.json`; every subsequent run for
  that MCU reuses the cache (~0.03s). It is a one-time cost per MCU, not per run.
- **Prompt caching** (Groq/others offer input caching at ~50% off) would cut the
  device+MCU input further since those maps are byte-identical across a run's
  retries — not modeled above; the numbers are the un-cached worst case.
