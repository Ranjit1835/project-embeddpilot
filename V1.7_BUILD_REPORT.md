# V1.7 Build — Complete Driver Scope via MCU Reference-Manual Ingestion

Extends EmbeddPilot from items 1–3 (identify peripheral, register map, bit
fields) to all seven, by ingesting the target MCU's reference manual into a
cached **MCU map** and generating + validating the host-side bring-up (clock,
GPIO/AF, init, error handling) against it. Target: **STM32F4 / RM0090 / I2C1**.
ESP32 and single-document device flows are untouched.

Built after the feasibility spike passed (see `V1.7_SPIKE_REPORT.md`).

## Pieces delivered

1. **Prose bit-field extractor** (`ingestion/prose.py`). Parses `Bit N NAME:` /
   `Bits N:M NAME:` reference-manual prose into bit fields with exact positions —
   the spike's key finding was that the bit-diagram summary TABLES reverse cell
   order (`devreseR/FPOTS` = Reserved/STOPF reversed) while the prose is clean.
   Also pairs register-section headings with offset/reset. `merge_prose_fields`
   combines table offsets with prose bit-field names.

2. **Section locator** (`ingestion/rm_sections.py`). Reads the PDF outline
   (RM0090: 2201 bookmarks in ~2s) → per-chapter page ranges, with silicon-
   variant pinning (RM0090 has parallel RCC chapters per die family).

3. **MCU ingestion** (`ingestion/mcu_pipeline.py`). Section-targeted extraction
   of the RCC/GPIO/peripheral register sections, merged (table offsets + prose
   bit fields). Separate path from `ingest_datasheet`.

4. **MCU-map schema + cache** (`schema/mcu-map.schema.json`,
   `ingestion/mcu_cache.py`). Derives the cross-checkable
   `clock_enables` table (peripheral→bus→register→bit, e.g. I2C1→APB1→
   RCC_APB1ENR→bit 21) and `reset_controls`; records `rm_revision`
   ("RM0090 Rev 19"). Per-MCU cache keyed by (family, variant, peripheral) —
   ingest once (~13s), reuse in ~0.03s. The cache is the round's asset: a
   growing library of supported MCUs.

5. **Generation with both maps** (`generation/worker.py`,
   `generation/pipeline.py`). The worker prompt gains an MCU CONFIGURATION
   section: clock enable, GPIO/pin config (pins + AF number are USER INPUT, not
   invented), peripheral init + I/O, error handling. It requires named,
   cross-checkable bit/offset defines and stamps prose-derived init sequences
   with a SEQUENCE-UNVERIFIED marker.

6. **Validation** (`validator/mcu_crosscheck.py`, `validator/crosscheck.py`,
   `validator/__main__.py`, `validator/stubs/stm32/`). New MCU cross-check:
   every RCC/GPIO/peripheral bit position and register offset a driver defines
   must match the MCU map — a wrong clock bit (22 for I2C1's 21) is a hard
   failure, same rule as device offsets. The device cross-check skips MCU-owned
   defines so they don't false-fail. The SEQUENCE marker → `validated-with-
   unverified-fields`. A CMSIS-style STM32 stub header lets the judge compile
   generated bring-up under real `arm-none-eabi-gcc` (compile-only, mirrors the
   V1.6.0 esp32 stub).

## Definition of done

- **Complete STM32F4 I2C1 driver validates end-to-end — proven BOTH ways:**
  - **Live** (NVIDIA `openai/gpt-oss-120b`): a BME280-on-STM32F4-I2C driver
    generated from the two maps reached `validated-with-unverified-fields` in 3
    attempts — real `arm-none-eabi-gcc` compile pass, device register
    cross-check pass, MCU RCC/GPIO cross-check pass (clock-enable + GPIO bits
    verified against the map), RM init sequence marked UNVERIFIED.
  - **Deterministic** (`tests/test_v17_endtoend.py`): a fixed complete driver
    through the REAL validator with the same result, plus a wrong clock bit
    caught end-to-end.
- **Extraction proven on the real RM0090**: `RCC_APB1ENR` I2C1EN = bit 21,
  `RCC_AHB1ENR` GPIOA = bit 0, I2C_SR1 error flags (BERR/ARLO/AF/OVR) — all
  clean, all cross-checkable.
- **140 tests pass.** ESP32 and single-document flows unregressed; contamination
  guard, subprocess boundary, and three-state verdicts unchanged.

## Provider & retry (what made live generation work)

- **NVIDIA provider** (`generation/provider.py::NVIDIAProvider`, selected by
  `make_provider()` when `NVIDIA_API_KEY` is set). NVIDIA's OpenAI-compatible
  endpoint hosts the same `openai/gpt-oss-120b` with a large context/output
  window. The both-maps complete-driver prompt **413s on Groq's ~8000-TPM free
  tier** but fits on NVIDIA — that is what unblocked live generation.
- **Targeted-edit retry** (gated to large-window providers via
  `provider.large_window`). On retry the worker is handed its OWN prior failing
  file and told to fix only the named error. This closes the V1.6.1-deferred
  cold-reroll finding — which was deferred precisely because echoing prior code
  did not fit Groq's window. With NVIDIA it fits, and it is what let the live
  driver converge (attempt 3) instead of re-rolling new -Werror slips each time.
  Groq keeps the cold re-roll (echo would 413), so the device-only path is
  unchanged.
- **AF ↔ peripheral mapping (item 5) needs the device datasheet.** The RM's GPIO
  chapter has the AFRL/AFRH mechanism but not the pin→AF#→peripheral table
  (which lives in the device datasheet, per the spike). So pin/AF numbers are
  treated as USER INPUT and the AF *number* is not yet cross-checked against a
  table — a follow-up (ingest the datasheet AF table) would close it.
- **Init sequence (item 6) is partial and marked UNVERIFIED**, as the spike
  predicted — the registers/bits it touches are cross-checked; the ordering is
  transcribed from prose and honestly flagged.
- **UI scope-honesty panel deferred** to a follow-up (per the round's cadence
  decision) — the "which of 7 items are covered/unverified" surface is backend-
  ready (the report already carries the checks + unverified list).
