# V1.7 Feasibility Spike — MCU Reference Manual Ingestion (STM32F4 / RM0090)

**Goal of the spike (per kickoff):** attempt section-targeted extraction of the
STM32F4 reference manual for one peripheral (**I2C1**), report honestly what is
extractable / partial / unrecoverable for items 4–7, measure cost, then STOP for
a gate decision. No build.

**Input:** `extraction/input/rm0090.pdf` — 1751 pages, 21.5 MB (under the 50 MB
loader cap). Real ST RM0090. Target peripheral: **I2C1**.

## Section locator — WORKS

Read the PDF outline via pdfminer (pdfplumber's backend): **2201 bookmark
entries, opened in 2.3 s**, each resolvable to an exact page. Located every
target chapter deterministically:

| Chapter | Pages | Key subsections |
|---|---|---|
| 6 RCC (F42/43xxx) | 150–~267 | `RCC_APB1ENR` p183, `RCC_AHB1ENR` p180, `RCC_APB1RSTR` p174, RCC reg-map table p210–212 |
| 8 GPIO | 267–289 | MODER/OTYPER/OSPEEDR/PUPDR p281–282, AFRL p285, AFRH p286, reg-map p287 |
| 27 I2C | 839–873 | master mode 27.3.3 p846, SR1 p865, SR2 p868, CR1 p860, reg-map p872 |

Section-targeting is therefore viable and necessary (see cost below).

## The single most important extraction finding

**Bit fields must be parsed from "Bit N NAME:" PROSE, not the bit-diagram
summary tables.** When the current pipeline extracted I2C register bit fields
from the register-map *table* (Table 125, p872), the bit-cell text came out
**reversed**: `devreseR / FPOTS / FTB / RDDA` (= Reserved / STOPF / BTF / ADDR
reversed) — a right-to-left cell-order artifact of pdfplumber on those grids.
The detailed per-bit prose ("`Bit 10 AF: Acknowledge failure`") is **clean and
unambiguous**, and a simple `^Bits?\s+\d+(?::\d+)?\s+[A-Z0-9_]+:` parser
recovered **17/17** I2C_CR1 bits and all SR1 error flags correctly.

Consequence for the build: register **offsets** extract fine today (from summary
tables), but **bit-field names are currently mangled** on this document. V1.7's
first build item is a prose bit-field extractor. The spike proves it is
tractable and high-recovery.

## Cost & performance

- **Extraction is deterministic (pdfplumber) — zero LLM tokens for ingestion.**
  The only LLM cost is at generation time (device map + MCU map → worker); the
  I2C1 MCU map (clock enables + reset + GPIO regs + I2C regs + error flags +
  init prose) is a few KB, well within the existing token budget.
- **Targeted extraction:** ~0.2 s/page — the 38 spike pages took **8.0 s**.
- **Whole-document extraction:** 1751 pp × ~0.2 s ≈ **~6 minutes** of text/table
  parsing alone. Per-run whole-RM ingestion is unacceptable → **per-MCU caching
  is mandatory** (matches the kickoff; the cache is the round's real asset).

## Caveats surfaced

- **Silicon-variant split:** RM0090 has parallel RCC chapters (ch6 =
  STM32F42xxx/43xxx; the F405/07/415/17 line has its own). Extraction must pin
  the target variant per MCU or it will conflate register banks.
- **Diagrams remain unrecoverable** (transfer-sequence figures on p846–850,
  p849/850) — expected, matches WS1's bit-diagram precedent.
- **AF mapping** needs the device datasheet (above).

## Gate recommendation: **PASS — proceed to build V1.7**

Feasibility holds: clock and error conditions are extractable AND
cross-checkable (the core payoff), GPIO registers extract, init prose is
partially recoverable and honestly markable. Section-targeting + outline
location works in seconds; caching handles the size. Build with these
spike-derived requirements:

1. **Prose bit-field extractor** (`^Bit N NAME:`), replacing reliance on the
   reversed bit-diagram tables — the top build item.
2. **Section locator** via PDF outline → per-chapter page ranges; **pin the
   silicon variant**.
3. **MCU map schema** (distinct from the device register map): clock enables
   (peripheral→bus→register→bit), reset regs, GPIO port regs, I2C control/status
   regs with error flags, extracted init prose (marked UNVERIFIED) — every entry
   with `source_pages` + confidence, WS1 discipline.
4. **AF/pin validation needs the device datasheet** (third document); pin
   selection is user input validated against it, never auto-picked.
5. **Per-MCU caching** with RM version/revision recorded.
6. **Validation:** RCC/GPIO/I2C register+bit usage cross-checked against the MCU
   map (hard fail on mismatch, same as device offsets); AF numbers vs the AF
   table; init/error prose marked UNVERIFIED → `validated-with-unverified-fields`.
   Real `arm-none-eabi-gcc` compile stays mandatory for STM32. ESP32 + existing
   single-doc flow unchanged.

**Status:** spike only — no schema, extractor, or pipeline code written. Awaiting
gate decision before any build.
