# V1.9 Spike — Minimal / Prose-Style Register Extraction

**Spike, not a build.** Findings + gate recommendation. No schema, pipeline, or UI
changes were made; only throwaway diagnostic scripts (removed).

## Method

Five minimal-style documents examined:
- **TMP100** (Texas Instruments, I2C) and **TMP125** (TI, SPI) — from V1.8 held-out testing.
- **LM75B** (NXP, real datasheet — TI SNIS153D second-source) — held-out.
- **MCP9808** (Microchip) and **SHT31** (Sensirion) — held-out, but see the note below.

**Honesty note on the held-out set:** the MCP9808 and SHT31 files provided are
**Adafruit tutorial *guides*, not vendor datasheets** — their text is library
installation, WipperSnapper, CircuitPython, etc., with no register specification.
They correctly extract 0 registers because there is nothing to extract, but they
do **not** test datasheet extraction. The valid held-out datasheet is **LM75B
(NXP)**, and it confirms the key pattern across a second vendor. A fuller held-out
pass should use the real Microchip MCP9808 (DS20005095) and Sensirion SHT3x
datasheets; the conclusions below are drawn from TMP100 + TMP125 + LM75B, all real
datasheets.

## Findings — minimal sensors fall into three patterns

### Pattern A — pointer-register I2C sensors → RECOVERABLE (dominant pattern)
**Documents:** TMP100 (TI), LM75B (NXP). Both extract **0 registers today**.

1. **Presentation.** A **pointer register** selects among a few data registers.
   TMP100 **p.15 Table 5** `[P1, P0, TYPE, REGISTER]`: `00→Temperature (R)`,
   `01→Configuration (R/W)`, `10→T_LOW`, `11→T_HIGH`. LM75B is identical in shape
   (pointer → Temp/Conf/T_HYST/T_OS). The register *structure* is often a **figure**
   (TMP100 Figure 10); config bit fields (`OS/R1/R0/F1/F0/POL/TM/SD`) are in **prose**.
2. **Stage that drops it: the PARSER (`classify_table`/`registers.py`).** The
   classifier correctly flags the pages and pdfplumber extracts the tables, but the
   pointer-address table's "address" is a **split 2-bit binary pointer** (columns
   `P1`,`P0`) or a `[pointer, register]` pair — matching none of the three handled
   shapes → `other`. **Compounding bug:** in *both* TMP100 and LM75B a
   **temperature→digital-output lookup table false-positives as
   `register_index_headerless`** and parses to 0 registers, masking the real gap.
3. **Recover, at what confidence.** (a) a **pointer-register table parser** (pointer
   value → address `0x00..0x03`) — **medium-high** (the table is clean text);
   (b) **suppress the temp-lookup false positive** — small, high-confidence;
   (c) config **bit fields from prose** → **low**, carried as UNVERIFIED (the
   V1.6.1 pattern).
4. **Right abstraction?** Yes, **but the schema needs a pointer-register concept.**
   Access is "write the pointer byte, then read/write N data bytes" — not the
   direct `reg address == offset` the schema assumes. **FLAG FOR APPROVAL.**

### Pattern B — fixed-readout devices → NOT a register problem (TMP125)
1. **Presentation.** No registers exist. TMP125 **p.5**: a fixed 16-bit SPI word
   (`D15..D0 → 0,T9..T0`) + a temperature→code table; shutdown is a 16-clock SPI
   pattern, not a register. Full-text: 0 "pointer", 0 "configuration register".
2. **Stage.** None — the parser correctly yields 0 because there is nothing.
3. **Recover.** Nothing to recover at the register level.
4. **Right abstraction?** **No.** Needs a **no-register-map "fixed readout" device
   shape** (bus, bit width, value bit-slice, sign, LSB weight). **FLAG FOR APPROVAL.**

### Pattern C — command-word devices → reuse the existing `commands` concept (SHT3x)
Only the Adafruit *guide* was available, so this is characterized from the known
SHT3x datasheet, not measured here. SHT3x is **command-based**: send a 16-bit
command (e.g. `0x2400`), read data words — no addressable registers. The canonical
schema **already has a `commands` array** (added in the WS1 spike for W25Q64
opcodes). The gap is **command-table extraction tuned for 16-bit sensor commands**;
likely reuses `commands` rather than new schema. **Lower priority; needs the real
datasheet to spec.**

## Gate recommendation: **PROCEED to a scoped build**

The evidence shows **real, vendor-general structure**, not one-off bugs. The
pointer-register pattern is confirmed on two independent real datasheets from two
vendors (TI, NXP) and is the dominant architecture for simple I2C sensors
(TMP100, LM75, MCP9808, and many more). Building to it is grounded extraction, not
guessing. Ordered build requirements the evidence supports:

1. **Fix the temperature-lookup false positive** in `classify_table` — a
   temp→code table must not classify as a register index. Small, pure correctness
   win; also unblocks honest Pattern-A detection. *(No schema change.)*
2. **Pointer-register table parser + schema pointer-register concept**
   `[APPROVAL REQUIRED]` — recognize the `[P1,P0,TYPE,REGISTER]` / `[pointer,
   register]` shape, map pointer bits → address, and record the write-pointer-then-
   read access pattern. Covers Pattern A across vendors.
3. **No-register-map "fixed readout" device shape** `[APPROVAL REQUIRED]` — for
   TMP125-class parts (bit width, value bit-slice, sign, LSB). The generator emits a
   read-and-scale driver; the scope panel says "no register map — fixed readout,"
   not a skipped cross-check read as failure.
4. **(Later) command-word sensor extraction** — reuse the existing `commands`
   array; needs the real SHT3x datasheet to spec. Lowest priority.

## Approval-gated canonical-schema additions (do NOT introduce silently)
Exactly as the `commands` array was flagged in the WS1 spike:
- **A pointer-register concept** (address = pointer value; access = write pointer → read/write N bytes).
- **A no-register-map fixed-readout device shape** (bit-slice + scaling, no addressing).

## What stays unrecoverable (for scope-panel honesty)
- **Bit fields present only in prose or figures** → generated but carried UNVERIFIED (never silently "verified").
- **Genuinely register-less devices** (TMP125) → there is no register map to cross-check; the panel must state "no register map — fixed readout (N/A)", distinct from "skipped (toolchain missing)" and from a real failure.
- **Tutorial guides** (the MCP9808/SHT31 files as provided) are not datasheets and can never yield a register map — an input-quality issue, not an extraction gap.

**Stop. No build until the gate decision** on requirements 1–4 and the two schema additions.
