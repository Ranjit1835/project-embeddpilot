# V1.6.1 — Generation Reliability Fix

**Scope:** urgent round. A live BMP085 (I2C pressure sensor) run on the deployed
UI exhausted every retry and never reached a validated verdict. Fixed before V2.
No chat/repo-gen/application code touched.

## Step 0 — Diagnosis (reproduced end-to-end)

Reproduced through **real ingestion** of `extraction/input/bmp180.pdf` (BMP180 is
register-compatible with BMP085) on platform `raspberry-pi`, then routing →
worker → real validator with Groq.

**Ingested map (deterministic):** chip BMP180, 28 registers, 5 commands, offsets
`0xAA–0xF8` (all < 0x100), **`base_address = None`**, no warnings.

**Per-attempt behaviour (representative run):**
- Attempt 1: `register_crosscheck` ✓, `compile` ✗ — generated-code cleanliness
  slips (`memcpy` without `<string.h>`; `printf("%d", int32_t)` format).
- Attempt 2: fed attempt-1's compiler diagnostics verbatim → worker changed the
  named lines → **validated**.
- Other runs: the worker mis-transcribed the BMP180 pressure-compensation
  algorithm with an **unbalanced parenthesis** (e.g.
  `p = p + ((p>>8)*(p>>8)*3038 >> 16) + 3791) >> 4;`) — the exact class the
  field report showed (`... + 2) >> 2;`). When that happened, the cold retry
  loop failed to converge and the run went `unvalidated`.

**Answers to the Step-0 questions**
- Same error repeating or different? **Different each attempt.** The retry loop
  works when the fix is easy; it fails to converge on the hard compensation math.
- Exact retry feedback? The validator's failure list verbatim
  (`format_failures`), no worker reasoning leaked.
- Did later attempts change the failing lines? **Yes** — the worker acts on
  feedback when it can see what to change.

## Which proposed fixes the evidence supported

| Proposed | Verdict | Evidence |
|---|---|---|
| **1 — base inference fired on the sensor** | ❌ Not the cause | `base_address` is already `null`; inference requires offsets ≥ 0x10000, impossible for a byte-addressed sensor. |
| **1′ — framing label decoupled from base** | ✅ Real bug | The router chose framing from register **count**, never `base_address`, so a bus sensor's prompt carried `Driver framing: register-based` over a `base_address: null → BUS-ATTACHED` addressing contract — contradictory signals. |
| **2 — generated code must compile clean** | ✅ | Attempt-1 failures were exactly this class (field report: unused param + parens; repro: missing include + format). |
| **3 — mark transcribed computation** | ✅ Strongly | A repro run returned a clean `validated` with the full compensation algorithm present and **zero** unverified markers — the silent-wrong-math blind spot. |
| **4 — toolchain mismatch labeling** | ✅ (finish it) | The note named the actual compiler but not the **requested** one. |
| **Also-fix — sample provenance** | ✅ | All three sample maps asserted `{chip: user, peripheral: user}` though no user supplied them. |
| **(New) crosscheck `_CMD_MASK` false positive** | ✅ Found in repro | `BMP180_CTRL_MEAS_CMD_MASK` (a bit-mask) was classified as an **opcode** (`_CMD` substring) and cross-checked against the commands array → false hard-fail. Same family as the V1.6.0 `_ADDR` fix. |
| **(New) cold-reroll retry weakness** | ⚠️ Real, deferred | See below. |

## What changed

1. **Fix 1′ — framing follows `base_address`** (`generation/router.py`). New
   `bus` framing when `base_address` is null (non-command); `register` only when
   a real base is present. The route line now reads
   *"…base_address null → bus-attached (I2C/SPI) transfer-callback framing"* and
   agrees with the worker's addressing contract.
2. **Fix 2 — compile-clean generation** (`generation/worker.py`). Strengthened
   rule 4 (applies to EVERY file incl. example stubs: consume every parameter
   via `(void)param;`, include headers you use, match printf conversions), plus
   an inline stub reminder. **The judge was not relaxed.**
3. **Fix 3 — mark transcribed computation** (`generation/worker.py`,
   `validator/report.py`, `validator/crosscheck.py`, `validator/__main__.py`).
   The worker precedes compensation/conversion functions with a computation
   `UNVERIFIED` marker; the validator records each in a new
   `unverified_computations` list; `finalize()` downgrades to
   `validated-with-unverified-fields` when present. The math is **not** verified
   (deferred to V2/V3) — the round's requirement is honesty about what was not
   checked.
4. **Fix 4 — requested-vs-actual toolchain** (`validator/compile_check.py`).
   Fallback note now reads *"NOT TARGET-ACCURATE: platform 'X' requests
   `<want>`, … compiled with `<actual>` instead …"*, naming both. (UI panel
   wiring deferred to a follow-up per scope decision — backend/data only here.)
5. **Also-fix — truthful sample provenance** (`generation/inputs.py`,
   `artifacts/*-extracted-map.json`). New `sample` provenance value accepted by
   the gate; the three sample maps relabelled from the untrue `user`.
6. **Crosscheck `_CMD_MASK` fix** (`validator/crosscheck.py`). `_MASK`/`_POS`
   classification now wins over the `_CMD`/`_ADDR`/`_REG` substring heuristics,
   so a field mask is never cross-checked as an opcode.

## Definition of Done

- **BMP-style bus sensor reaches a terminal verdict end-to-end:** proven
  deterministically through the **real validator** (`generate_validated_driver`
  + subprocess judge) — framing `bus`, `register_crosscheck` pass (CMD_MASK not
  false-failed), `compile` pass, and **`validated-with-unverified-fields`** with
  the compensation math surfaced. See
  `tests/test_ws2_pipeline.py::test_bmp_bus_sensor_reaches_terminal_verdict`.
- **Framing regression tests pass:** BMP085 (bus), BMP180 (bus), ESP32
  (memory-mapped register).
- **Full suite green:** 89 passed. Validator strictness, three-state verdicts,
  subprocess boundary, and the contamination guard are unchanged (guard test
  still passes; the worker↔validator marker agreement is by a shared literal
  substring, not an import).

## Still open / deferred (flagged)

- **Cold-reroll retry weakness (root reliability limiter).** The retry passes the
  worker only the validator's error text, **not the worker's own previous code** —
  so "line 114: unbalanced paren" is un-actionable and the worker re-rolls the
  whole hard algorithm. Echoing the prior failing file back for a **targeted
  edit** converges far better, but does **not** fit the free Groq tier: measured,
  echoing all three files → HTTP 413 (admission), and even the single failing
  file starves the output reservation into truncation on the ~8000-TPM ceiling.
  **Deferred to V2** with a larger token budget (paid tier / bigger
  context+output model). Left a code note at the retry site.
- **Live cloud re-confirmation** of a green BMP180 run was **not** captured this
  round because the repeated diagnosis runs exhausted the Groq free-tier daily
  budget (429). The terminal verdict is proven deterministically via the real
  validator instead; a live run should be re-checked once the budget resets.
- **Compensation-math correctness** (a wrong shift that compiles) remains a
  V2/V3 problem, as scoped. This round makes it **honest** (unverified), not
  verified.
